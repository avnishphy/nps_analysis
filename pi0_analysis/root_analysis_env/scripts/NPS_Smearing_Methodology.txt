1. INTRODUCTION AND PHYSICS MOTIVATION
================================================================================

1.1 Overview
------------
The NPS calorimeter is designed to detect neutral particles (photons) from 
π⁰ decay in electron scattering experiments. The π⁰ meson decays 
electromagnetically via π⁰ → γγ with a branching ratio of ~98.8%.

The invariant mass of the two-photon system should reconstruct to the π⁰ mass:
    m_π⁰ = 134.9768 MeV/c² (PDG value)

However, experimental measurements suffer from:
    (a) Energy resolution effects - finite energy measurement precision
    (b) Position resolution effects - finite cluster position determination
    (c) Calibration uncertainties - systematic energy scale offsets

1.2 Goals of Smearing Analysis
-------------------------------
Our primary objectives are:

1. Determine optimal smearing parameters (μ, σ, σ_pos) for each calorimeter 
   section that make simulation match experimental data

2. Quantify the detector's energy resolution and position resolution 
   independently for each calorimeter section

3. Apply these smearing parameters to Monte Carlo simulation to produce 
   realistic detector response for physics analyses

4. Enable accurate background subtraction and acceptance corrections by 
   matching simulation to data distributions

1.3 Section-by-Section Calibration
-----------------------------------
The NPS calorimeter is divided into spatial sections (typically 9×9 grid). 
Each section has independent calibration because:

    - Different positions have different light collection efficiencies
    - Electromagnetic shower development varies with impact position
    - Edge effects and inter-module gaps affect energy deposition
    - Cluster reconstruction algorithms have position-dependent biases

Therefore, we perform independent optimization for EACH section.

2. THEORETICAL FRAMEWORK
================================================================================

2.1 Photon Detection and Reconstruction
----------------------------------------
For each detected photon cluster, we measure:
    - Energy: E_measured (from summed ADC signals)
    - Position: (x, y) in cm at the NPS plane
    - Distance to NPS: z = z_NPS (typically ~430 cm from target)

The photon 4-momentum is reconstructed assuming massless particle:
    
    r = √(x² + y² + z²)               [distance from target to cluster]
    
    p⃗ = E · (x/r, y/r, z/r)          [momentum direction from geometry]
    
    4-momentum: (E, p_x, p_y, p_z) = (E, Ex/r, Ey/r, Ez/r)

2.2 Invariant Mass Reconstruction
----------------------------------
For π⁰ → γ₁γ₂ decay, the invariant mass is calculated:

    M² = (E₁ + E₂)² - (p⃗₁ + p⃗₂)²
    
    M² = (E₁ + E₂)² - [(p₁ₓ + p₂ₓ)² + (p₁ᵧ + p₂ᵧ)² + (p₁ᵧ + p₂ᵧ)²]

For massless photons: |p⃗| = E, so the momentum components are:
    
    pₓ = E · x/r,    pᵧ = E · y/r,    pᵢ = E · z/r

2.3 Opening Angle and Kinematics
---------------------------------
The opening angle θ₁₂ between photons affects mass resolution:

    cos(θ₁₂) = (p⃗₁ · p⃗₂)/(|p⃗₁||p⃗₂|) = (x₁x₂ + y₁y₂ + z²)/(r₁r₂)

For small opening angles (typical at high π⁰ momentum):
    
    M_γγ ≈ √(2E₁E₂(1 - cos θ₁₂))  ≈  √(2E₁E₂) · θ₁₂/√2

This shows mass resolution depends on BOTH energy and angular resolution.

3. SMEARING PARAMETERS AND PHYSICAL MEANING
================================================================================

We model detector effects with THREE independent parameters:

3.1 Parameter μ (mu): Energy Scale Factor
------------------------------------------
Physical meaning: Multiplicative calibration constant
Range: [0.8, 1.2] (typically near 1.0)
Step size: 0.01

The "true" photon energy E_true is related to measured energy by:
    
    E_corrected = μ · E_measured

If μ < 1.0: Detector under-responds (measures less than true energy)
If μ > 1.0: Detector over-responds (measures more than true energy)

Sources of energy scale offset:
    - Miscalibration of ADC gains
    - Incorrect scintillator light yield assumptions
    - PMT gain drifts
    - Energy leakage corrections
    - Shower containment systematics

3.2 Parameter σ (sigma): Energy Resolution
-------------------------------------------
Physical meaning: Relative energy resolution (stochastic term)
Range: [0.03, 0.08] (3% to 8% typical for calorimeters)
Step size: 0.002

Energy resolution follows approximately:
    
    σ_E/E = σ (assumed constant in our model)

In reality, energy resolution often follows:
    
    σ_E/E = a/√E ⊕ b ⊕ c/E

where ⊕ denotes quadrature sum. Our simplified model uses constant σ.

Physical sources of energy resolution:
    - Photoelectron statistics (Poisson fluctuations)
    - Electromagnetic shower fluctuations
    - Light collection non-uniformity
    - Electronic noise
    - Pile-up effects

Smearing application:
    
    E_smeared = μ · E_measured · G(1.0, σ)
    
where G(1.0, σ) is Gaussian random number with mean 1.0 and std dev σ.

3.3 Parameter σ_pos (sigma_pos): Position Resolution
-----------------------------------------------------
Physical meaning: Cluster position uncertainty (RMS)
Range: [0.0, 2.0] cm
Step size: 0.01 cm

Position resolution represents uncertainty in determining cluster centroid.

Physical sources of position resolution:
    - Crystal/module granularity (finite segmentation)
    - Energy sharing between adjacent modules
    - Shower profile reconstruction algorithms
    - Signal-to-noise ratio (low E → worse position resolution)
    - Non-linear energy weighting in centroid calculation

Smearing application (applied INDEPENDENTLY to x and y):
    
    x_smeared = x_measured + G(0, σ_pos)
    y_smeared = y_measured + G(0, σ_pos)

where G(0, σ_pos) is Gaussian with mean 0 and RMS = σ_pos cm.

IMPORTANT: Position smearing affects the photon momentum direction, which 
then affects the invariant mass through the angular term. This coupling 
between position and mass resolution is fully captured in our methodology.

3.4 Order of Operations: Energy First, Then Position
-----------------------------------------------------
The correct physical workflow for smearing is:

    1. Apply energy smearing: E_i → E_i'
    2. Apply position smearing: (x_i, y_i) → (x_i', y_i')
    3. Compute smeared photon 4-momentum with (E_i', x_i', y_i', z_NPS)
    4. Calculate invariant mass from two smeared photons

This order ensures:
    - Energy and position are smeared independently (no artificial correlation)
    - Photon 4-momentum conservation is maintained (p⃗ = E · r̂)
    - Angular resolution effects naturally propagate to mass resolution

4. CHI-SQUARED MINIMIZATION METHODOLOGY
================================================================================

4.1 Definition of Chi-Squared
------------------------------
We use chi-squared to quantify agreement between data and smeared simulation:

    χ² = Σᵢ [(N_data,i - N_sim,i)² / N_data,i]

where:
    - Sum runs over all histogram bins i (typically 100 bins)
    - N_data,i = number of data events in bin i
    - N_sim,i = number of smeared simulation events in bin i

We use data counts in denominator (not simulation) for statistical weighting.

4.2 Why Chi-Squared?
--------------------
Chi-squared is appropriate because:

1. It quantifies bin-by-bin agreement weighted by statistical uncertainty
2. Lower χ² indicates better data-simulation agreement
3. Well-established in particle physics for histogram comparisons
4. Robust to differences in overall normalization (can scale histograms)

4.3 Minimization Strategy
--------------------------
We seek parameters (μ, σ, σ_pos) that minimize χ²:

    (μ_best, σ_best, σ_pos_best) = argmin χ²(μ, σ, σ_pos)

This is a 3-dimensional optimization problem in continuous parameter space.

4.4 Monte Carlo Evaluation
---------------------------
For EACH set of trial parameters (μ, σ, σ_pos), we:

1. Loop over ALL simulation events in the section
2. For EACH event, perform N_smear independent smearing iterations:
    a. Draw 2 random energy scale factors: G(μ, σ)
    b. Draw 4 random position offsets: G(0, σ_pos)  [for x₁, y₁, x₂, y₂]
    c. Apply smearing to both photons
    d. Calculate invariant mass
    e. Fill histogram with this mass value

3. After processing all events × N_smear, compare histogram to data
4. Calculate χ² from bin-by-bin comparison

Parameter N_smear:
    - Default: N_smear = 20 for energy-only optimization
    - Increased: N_smear_pos = 50 for position optimization
    - Higher N_smear reduces Monte Carlo statistical noise but increases 
      computation time linearly

4.5 Statistical Uncertainty in χ²
----------------------------------
Each χ² evaluation is subject to Monte Carlo uncertainty. For N_smear 
repetitions, the relative uncertainty in χ² is approximately:

    Δχ²/χ² ≈ √2 / √(N_bins × N_smear)

For N_bins = 100 and N_smear = 20:
    Δχ²/χ² ≈ √2 / √2000 ≈ 0.032 ≈ 3.2%

However, in practice we observe ~5-7% fluctuations, likely due to:
    - Non-Gaussian tails in distributions
    - Low-statistics bins contributing disproportionately
    - Correlations between bins

For critical position optimization, we increase to N_smear = 50:
    Δχ²/χ² ≈ √2 / √5000 ≈ 0.020 ≈ 2.0%

This reduces Monte Carlo noise from causing apparent χ² increases during 
optimization.

5. OPTIMIZATION ALGORITHM: ITERATIVE REFINEMENT
================================================================================

5.1 Challenge: Parameter Coupling
----------------------------------
The three parameters (μ, σ, σ_pos) are NOT independent:

    - Changing σ_pos affects angular resolution → affects mass distribution 
      shape → may require re-adjustment of μ and σ
    
    - Energy scale μ shifts the mass peak → affects optimal σ_pos
    
    - Energy resolution σ broadens the mass peak → affects sensitivity to 
      position resolution

Therefore, sequential optimization (optimize μ,σ then add σ_pos) can give 
SUB-OPTIMAL results.

5.2 Solution: Iterative Refinement
-----------------------------------
We use a multi-stage optimization with feedback:

STAGE 1: Initial 2D Energy Optimization (σ_pos = 0)
    Purpose: Find good starting point for energy parameters
    Method: 2D grid scan over (μ, σ)
    Grid: 41 × 26 points 
          μ ∈ [0.8, 1.2] step 0.01
          σ ∈ [0.03, 0.08] step 0.002
    Total evaluations: 1066 chi-squared calculations
    N_smear: 20 (sufficient for energy-only optimization)

STAGE 2: Fine 2D Refinement (σ_pos = 0)
    Purpose: Improve precision around coarse minimum
    Method: Finer grid around coarse minimum
    Grid: 11 × 11 points
          μ ∈ [μ_coarse - 0.05, μ_coarse + 0.05] step 0.01
          σ ∈ [σ_coarse - 0.01, σ_coarse + 0.01] step 0.002
    Total evaluations: 121 chi-squared calculations
    N_smear: 20

STAGE 3: 1D Slice Scans for Visualization (σ_pos = 0)
    Purpose: Generate plots showing χ² profiles
    Method: Scan along μ direction and σ direction independently
    Not used for optimization, only for diagnostic plots

STAGE 4: Position Resolution Optimization
    Purpose: Find optimal σ_pos with current (μ, σ)
    Method: 1D scan over σ_pos with FIXED (μ, σ) from Stage 2
    Grid: σ_pos ∈ [0.0, 2.0] cm, step 0.01 cm
    Total evaluations: 201 chi-squared calculations
    N_smear: 50 (INCREASED to reduce MC noise)
    
    This finds σ_pos that minimizes χ²(μ_stage2, σ_stage2, σ_pos)

STAGE 5: Re-optimization of Energy Parameters
    Purpose: Re-optimize (μ, σ) with newly found σ_pos
    Method: 2D grid scan with σ_pos = σ_pos_stage4 FIXED
    Grid: Same as Stage 2 (11×11 around previous minimum)
    Total evaluations: 121 chi-squared calculations
    N_smear: 50 (keep higher for consistency)
    Iterations: Repeat up to 3 times if χ² improves by >1%
    
    This accounts for parameter coupling: the optimal (μ, σ) may shift 
    once position smearing is included.

STAGE 6: Final Position Refinement (Conditional)
    Purpose: Fine-tune σ_pos with re-optimized energy parameters
    Condition: Only if Stage 5 improved χ² by more than 1%
    Method: 1D scan over σ_pos with updated (μ, σ) from Stage 5
    Grid: σ_pos ∈ [max(0, σ_pos_old - 0.2), σ_pos_old + 0.2], step 0.01 cm
    Total evaluations: Up to 41 chi-squared calculations
    N_smear: 50

5.3 Convergence Criteria
-------------------------
Optimization terminates when:
    - Stage 5 iteration produces χ² improvement < 1%, OR
    - 3 iterations completed (typically converges in 1-2 iterations)

5.4 Why This Works
-------------------
The iterative approach handles parameter coupling by:

1. Finding good energy parameters first (most sensitive, well-constrained)
2. Adding position resolution on top
3. Feeding back to re-optimize energy (accounts for coupling)
4. Repeating until convergence

This is more robust than:
    - Pure 3D grid scan (computationally prohibitive: 41×26×201 ≈ 200k evals)
    - Sequential optimization without feedback (sub-optimal due to coupling)
    - Gradient-based methods (can get stuck in local minima with MC noise)

Total computation for one section: ~1500-2000 chi-squared evaluations
With N_events ~ 1000 and N_smear ~ 20-50: manageable on modern CPU

6. MONTE CARLO STATISTICAL CONSIDERATIONS
================================================================================

6.1 Sources of Statistical Uncertainty
---------------------------------------
Three sources contribute to uncertainty in χ² evaluation:

SOURCE A: Data Statistics
    - Limited number of experimental events
    - Poisson uncertainty in each histogram bin: Δᵢ = √Nᵢ
    - Contributes to denominator in χ² formula
    - FIXED for given dataset (cannot improve without more beam time)

SOURCE B: Simulation Statistics  
    - Limited number of simulated events
    - Affects numerator in χ² formula
    - Can be improved by generating more simulation events
    - NOT a major limitation in our analysis (typically 10k+ sim events/section)

SOURCE C: Monte Carlo Smearing Noise
    - Random number generation in smearing process
    - Different random seeds give different χ² even with same parameters
    - Scales as 1/√N_smear
    - THIS IS THE DOMINANT SOURCE we must control

6.2 Quantifying MC Smearing Noise
----------------------------------
We estimated MC noise by repeating χ² evaluation with different random seeds:

For N_smear = 20:
    - Observed χ² fluctuations: ±5-7%
    - Theoretical expectation: ±3.2%
    - Ratio: 2.0 (suggests non-Gaussian effects)

For N_smear = 50:
    - Observed χ² fluctuations: ±3-4%
    - Theoretical expectation: ±2.0%
    - Ratio: 1.7 (still some excess, but much improved)

6.3 Impact on Optimization
---------------------------
MC noise can cause:

PROBLEM 1: Apparent χ² increases during optimization
    Example: Stage 4 finds σ_pos = 0.35 cm with χ² = 66.94
             Stage 5 re-optimizes to χ² = 65.99
             But this looks like χ² INCREASED from 65.99 to 66.94
    
    Reality: Both values have ±3-4% uncertainty, so they're consistent
    
    Solution: Use N_smear = 50 for position stages → reduces noise to 
              acceptable level where real improvements are visible

PROBLEM 2: False minima in σ_pos scan
    With N_smear = 20, the χ² vs σ_pos curve has ±5% noise
    This can create spurious local minima
    
    Solution: Higher N_smear smooths the curve, reveals true minimum

PROBLEM 3: Premature convergence in Stage 5 iteration
    If MC noise is large, may think χ² improvement is <1% when it's actually 
    just noise
    
    Solution: N_smear = 50 ensures we can resolve 1% chi-squared differences

6.4 Computational Cost vs Statistical Precision
------------------------------------------------
Trade-off analysis for one chi-squared evaluation:

N_smear = 10:  ~10% uncertainty,  1.0× reference time
N_smear = 20:  ~7% uncertainty,   2.0× reference time  [OLD DEFAULT]
N_smear = 50:  ~4% uncertainty,   5.0× reference time  [NEW DEFAULT for pos]
N_smear = 100: ~3% uncertainty,  10.0× reference time  [future goal]

Our strategy:
    - Use N_smear = 20 for early energy optimization (Stages 1-3)
      Fast exploration, 7% noise is acceptable for finding coarse minimum
    
    - Use N_smear = 50 for position optimization (Stages 4-6)
      Critical for handling parameter coupling, need to resolve small 
      improvements reliably

6.5 Future Improvements
------------------------
To enable N_smear = 100+ without excessive computation time, we implemented 
performance optimizations (see Section 7).

7. PERFORMANCE OPTIMIZATIONS
================================================================================

7.1 Motivation
--------------
Computational bottleneck: Chi-squared evaluation repeated 1500-2000 times 
per section, with 10k+ events and N_smear = 20-50 per event.

Total operations per section: 1500 × 10000 × 50 ≈ 750 million smears

Even small per-operation overhead becomes significant at this scale.

7.2 Original Implementation Bottlenecks
----------------------------------------
BOTTLENECK 1: TLorentzVector Object Creation
    - Each smear iteration created 2 TLorentzVector objects
    - Constructor overhead + memory allocation
    - Operator overloading (operator+, M() method)
    - ~50-100 CPU cycles per object

BOTTLENECK 2: Individual Random Number Generation  
    - Called rng.Gaus() separately for each random draw
    - Internal state updates and algorithm overhead
    - Poor cache locality with scattered calls
    - ~30-50 CPU cycles per call

BOTTLENECK 3: Repeated Function Calls
    - nps::photon4vector() called 2× per smear
    - Redundant calculations (sqrt, divisions)
    - Function call overhead

BOTTLENECK 4: Redundant Calculations
    - Direction vectors (x/r, y/r, z/r) recalculated every smear
    - But only position changes, not z coordinate
    - sqrt(x² + y² + z²) repeated unnecessarily

7.3 Optimization Strategy 1: Direct Invariant Mass Calculation
---------------------------------------------------------------
BEFORE (Original Code):
    Vec4 ph1 = nps::photon4vector(E1_smeared, x1_smeared, y1_smeared, z_NPS);
    Vec4 ph2 = nps::photon4vector(E2_smeared, x2_smeared, y2_smeared, z_NPS);
    TLorentzVector g1(ph1[1], ph1[2], ph1[3], ph1[0]);
    TLorentzVector g2(ph2[1], ph2[2], ph2[3], ph2[0]);
    double mass = (g1+g2).M();

AFTER (Optimized Code):
    // Pre-compute geometric factors (outside loop for σ_pos=0)
    double r1 = sqrt(x1*x1 + y1*y1 + z_NPS*z_NPS);
    double r1_inv = 1.0 / r1;
    
    // Direct momentum calculation
    double px1 = E1_smeared * x1_smeared * r1_inv;
    double py1 = E1_smeared * y1_smeared * r1_inv;
    double pz1 = E1_smeared * z_NPS * r1_inv;
    
    // Same for photon 2...
    
    // Direct mass calculation
    double E_tot = E1_smeared + E2_smeared;
    double px_tot = px1 + px2;
    double py_tot = py1 + py2;
    double pz_tot = pz1 + pz2;
    double m_sq = E_tot*E_tot - px_tot*px_tot - py_tot*py_tot - pz_tot*pz_tot;
    double mass = (m_sq > 0) ? sqrt(m_sq) : 0.0;

Benefits:
    - Eliminated TLorentzVector overhead completely
    - 10 floating point ops vs ~50+ with object creation
    - Better compiler optimization (inlining, vectorization)
    - Improved cache locality

Expected speedup: 30-40% from this alone

7.4 Optimization Strategy 2: Batch Random Number Generation
------------------------------------------------------------
BEFORE (Original Code):
    for (int k=0; k<Nsmear; ++k) {
        double draw1 = rng.Gaus(mu, sigma);
        double draw2 = rng.Gaus(mu, sigma);
        double dx1 = rng.Gaus(0, sigma_pos);
        double dy1 = rng.Gaus(0, sigma_pos);
        double dx2 = rng.Gaus(0, sigma_pos);
        double dy2 = rng.Gaus(0, sigma_pos);
        // ... use random numbers ...
    }

AFTER (Optimized Code):
    // Pre-allocate arrays OUTSIDE event loop
    vector<double> rand_energy(Nsmear * 2);
    vector<double> rand_pos(Nsmear * 4);
    
    // For each event:
    for (int k=0; k<Nsmear*2; ++k) {
        rand_energy[k] = rng.Gaus(mu, sigma);
    }
    if (sigma_pos > 0) {
        for (int k=0; k<Nsmear*4; ++k) {
            rand_pos[k] = rng.Gaus(0, sigma_pos);
        }
    }
    
    // Use pre-generated random numbers
    for (int k=0; k<Nsmear; ++k) {
        double draw1 = rand_energy[k*2];
        double draw2 = rand_energy[k*2+1];
        // ...
    }

Benefits:
    - Better cache locality (sequential memory access)
    - Reduced function call overhead
    - Compiler can vectorize loops (SIMD instructions)
    - Can skip position random generation when sigma_pos = 0

Expected speedup: 20-30% from better cache usage

7.5 Optimization Strategy 3: Pre-compute Direction Vectors
-----------------------------------------------------------
For energy-only optimization (σ_pos = 0), positions don't change between 
smears, so direction vectors can be calculated ONCE:

BEFORE:
    for (int k=0; k<Nsmear; ++k) {
        double r1 = sqrt(x1*x1 + y1*y1 + z*z);  // REPEATED!
        double px1 = E1_smeared * x1 / r1;
        // ...
    }

AFTER:
    // OUTSIDE smear loop:
    double r1_sq = x1*x1 + y1*y1 + z_NPS*z_NPS;
    double r1_inv = 1.0 / sqrt(r1_sq);
    double ux1 = x1 * r1_inv;  // unit direction
    double uy1 = y1 * r1_inv;
    double uz1 = z_NPS * r1_inv;
    
    // INSIDE smear loop:
    for (int k=0; k<Nsmear; ++k) {
        double px1 = E1_smeared * ux1;  // just multiplication!
        double py1 = E1_smeared * uy1;
        double pz1 = E1_smeared * uz1;
        // ...
    }

Benefits:
    - Eliminates Nsmear sqrt() calls
    - sqrt() is expensive (~20-30 cycles)
    - For Nsmear=50: saves 50×6 = 300 sqrt calls per event!

Expected speedup: 15-25% for energy-only optimization

7.6 Optimization Strategy 4: Conditional Position Smearing
-----------------------------------------------------------
When σ_pos = 0, skip position smearing overhead entirely:

    if (sigma_pos > 0) {
        // Generate position random numbers
        // Apply position smearing
        // Recalculate direction vectors with smeared positions
    } else {
        // Use original positions directly
        // Use pre-computed direction vectors
    }

Benefits:
    - Stages 1-3 run with σ_pos = 0 → skip position smearing
    - Avoids unnecessary calculations and array allocations
    - Enables Strategy 3 optimizations fully

Expected speedup: 40-50% for energy-only stages

8.3 Histogram Configuration
----------------------------
Invariant mass histograms:
    Range: [0.08, 0.19] GeV/c²
    Bins: 100 bins → bin width = 1.1 MeV/c²
    
Choice of range:
    - π⁰ mass = 134.98 MeV/c² is near center
    - Allows for background below and above peak
    - Captures resolution tails (typically σ_mass ~ 10-15 MeV)
    - Avoids very low mass (combinatorial background)

8.4 Random Number Generation
-----------------------------
Generator: TRandom3 (Mersenne Twister)
Seed: Fixed at 42 for reproducibility
    - Same parameters → same χ² (debugging aid)
    - Change seed to estimate MC uncertainty

Gaussian generation: rng.Gaus(mean, sigma)
    - Uses Box-Muller transform internally
    - Generates pairs of independent Gaussians
    - High-quality random numbers (period 2^19937)

8.5 Spatial Sectioning
----------------------
Default: 9×9 grid of sections
X range: [-30, 30] cm (NPS width ~60 cm)
Y range: [-36, 36] cm (NPS height ~72 cm)

Section assignment:
    - Average position: x_avg = (x1 + x2)/2, y_avg = (y1 + y2)/2
    - Assign to section containing (x_avg, y_avg)
    - Ensures both photons are in approximately same detector region

Edge events:
    - Events outside nominal range still assigned to edge sections
    - May have lower statistics

9.3 Using Results in Analysis Code
-----------------------------------
The file simc_pi0_analysis.C reads section_map.csv and applies smearing:

STEP 1: Read CSV file
    Parse each row → create SmearingCoeffs structure
    Store in map: section_name → SmearingCoeffs

STEP 2: For each simulation event
    Calculate section from average position
    Look up SmearingCoeffs for that section
    Apply energy smearing with (μ, σ)
    Apply position smearing with σ_pos (both x and y)
    Reconstruct smeared photon 4-momenta
    Calculate smeared invariant mass

STEP 3: Fill histograms and continue analysis
    Now simulation includes realistic detector effects
    Can compare directly to data for physics extraction

IMPORTANT: Grid parameters in simc_pi0_analysis.C MUST match 
nps_sim_smearing.C, otherwise section assignments will be inconsistent!

10. USAGE AND INTERPRETATION OF RESULTS
================================================================================

10.1 Running the Analysis
--------------------------

Command line syntax:
    root -l -q 'nps_sim_smearing.C("data_file.root", "sim_file.root")'

Expected output:
    - Progress messages for each section
    - Chi-squared values for each optimization stage
    - Time estimates
    - Final summary table
    - Output files generated

Typical runtime:
    - 80 sections × 1500 evaluations × 10k events × 50 smears
    - ~30-60 minutes on modern CPU (after optimizations)
    - Previously ~60-120 minutes (before optimizations)

10.2 Interpreting χ² Values
----------------------------

GOOD FIT: χ²/Ndof ≈ 1.0
    For 100 bins with reasonable statistics
    χ² ~ 80-120 indicates good data-simulation agreement
    
POSSIBLE ISSUES:
    χ² << 100: May indicate over-fitting or statistical fluctuations
    χ² >> 100: Poor agreement, possible issues:
        - Incorrect simulation kinematics
        - Missing physics processes
        - Detector effects not captured by simple smearing
        - Data quality issues

Per-section χ² comparison:
    - Expect roughly similar χ² across sections
    - Significantly higher χ² in one section → investigate that region
    - Edge sections may have higher χ² (lower statistics, edge effects)

10.3 Interpreting Best-Fit Parameters
--------------------------------------

ENERGY SCALE (μ):
    μ = 1.00 ± 0.02: Well-calibrated detector (ideal)
    μ = 0.95-0.98:   Slight under-response (common for calorimeters)
    μ = 1.02-1.05:   Slight over-response (check calibration)
    |μ - 1| > 0.10:  Significant calibration issue, investigate!

ENERGY RESOLUTION (σ):
    σ = 0.03-0.05: Excellent resolution (3-5%)
    σ = 0.05-0.07: Good resolution (5-7%)
    σ ≈ 0.08:      Typical for NPS calorimeter
    σ > 0.10:      Poor resolution, check electronics/reconstruction

    Note: Energy resolution typically degrades with:
        - Lower energy (photoelectron statistics)
        - Off-center hits (shower containment)
        - Higher rates (pile-up)

POSITION RESOLUTION (σ_pos):
    σ_pos = 0.2-0.5 cm: Excellent position resolution
    σ_pos = 0.5-1.0 cm: Good position resolution
    σ_pos = 1.0-1.5 cm: Moderate resolution (typical)
    σ_pos > 2.0 cm:     Poor resolution or fitting artifact

    Note: Position resolution depends on:
        - Module/crystal size (granularity)
        - Energy (higher E → better S/N → better position)
        - Algorithm (center-of-gravity, fit, ML, etc.)

CONSISTENCY CHECKS:
    - Parameters should vary smoothly across sections
    - Sudden jumps suggest fitting problems or data issues
    - Central sections often have better resolution than edges

10.4 Diagnostic Plots
---------------------

PLOT 1: χ²(μ, σ) 2D scan
    - Should show clear minimum (valley)
    - Elliptical contours indicate parameter correlation
    - Multiple minima suggest problems

PLOT 2: χ²(σ_pos) 1D scan
    - Should show smooth parabola-like shape
    - Minimum should be well-defined (not at boundary)
    - Flat response → insensitive to position smearing

PLOT 3: Mass distributions (data vs smeared sim)
    - Visual check of fit quality
    - Peak position agreement
    - Width agreement
    - Tail behavior

PLOT 4: Residuals (data - sim)
    - Should be randomly distributed around zero
    - Systematic structure indicates model inadequacy
    - Large residuals in specific mass regions → investigate

10.5 Common Issues and Troubleshooting
---------------------------------------

ISSUE: χ² increases during optimization
    Cause: Monte Carlo statistical noise
    Solution: Increase N_smear, especially for position optimization
    Check: Re-run with different random seed, see if consistent

ISSUE: σ_pos optimization finds boundary value (0.0 or 2.0 cm)
    Cause: Insufficient sensitivity or wrong parameter range
    Solution: Check if position smearing actually affects mass distribution
              (small opening angles → insensitive to position)
              Extend range if needed

ISSUE: Parameters differ significantly between adjacent sections
    Cause: Low statistics, fitting noise, or real detector non-uniformity
    Solution: Check event counts, consider smoothing across sections,
              investigate detector hardware for those sections

ISSUE: Slow convergence in Stage 5 iteration
    Cause: Strong parameter coupling, MC noise
    Solution: Already handled by iteration limit (3 max)
              Higher N_smear can help

ISSUE: Smeared sim still doesn't match data after optimization
    Cause: Physics missing from simulation (FSI, radiative corrections)
           Detector effects beyond simple energy/position smearing
    Solution: Add additional smearing models (timing, PID, etc.)
              Check simulation input kinematics
              Consider non-Gaussian smearing models

11. KNOWN ISSUES AND LIMITATIONS
================================================================================

11.1 Physics Assumptions
-------------------------

ASSUMPTION 1: Constant energy resolution 
    Reality: σ_E/E typically has energy dependence (stochastic term dominates)
    Impact: May over-smear high-E photons or under-smear low-E photons
    Mitigation: Use restricted energy ranges, or implement E-dependent σ(E)

ASSUMPTION 2: Gaussian smearing
    Reality: Detector response may have non-Gaussian tails
    Impact: Discrepancies in distribution tails
    Mitigation: Could implement additional tail parameters

ASSUMPTION 3: Independent energy and position smearing
    Reality: Energy and position may be correlated (shower size affects both)
    Impact: Neglects correlation effects
    Mitigation: Generally small effect for π⁰ mass reconstruction

ASSUMPTION 4: Uniform position resolution
    Reality: Position resolution may depend on energy, impact position
    Impact: Position smearing may be too simple
    Mitigation: Section-by-section fit partially accounts for this

11.2 Statistical Limitations
-----------------------------

LIMITATION 1: Monte Carlo noise even with N_smear = 50
    χ² uncertainty: ~3-4% per evaluation
    Impact: Can obscure small improvements (<3%)
    Mitigation: Increased N_smear further (enabled by optimizations)

LIMITATION 2: Limited data statistics in edge sections
    Some sections have <500 events
    Impact: Poisson uncertainties affect χ² reliability
    Mitigation: Consider merging low-statistics sections

LIMITATION 3: Binning effects
    100 bins with ~1-2 MeV binning may miss fine structure
    Impact: Could over-smooth or miss narrow features
    Mitigation: Test with different binning schemes

11.3 Computational Limitations
-------------------------------

LIMITATION 1: Grid search not optimal for global minimum
    Could miss narrow minima between grid points
    Impact: Best-fit may be slightly sub-optimal
    Mitigation: Fine grid + iteration usually sufficient
               Could implement gradient-based refinement

LIMITATION 2: No parallelization
    CPU cores mostly idle during chi-squared scans
    Impact: Runtime could be reduced 8-16× with multi-threading
    Mitigation: OpenMP pragma additions would be straightforward

LIMITATION 3: Memory usage for batch RNG
    Pre-allocating arrays adds memory overhead
    Impact: Negligible for N_smear ~ 50, but scales linearly
    Mitigation: Currently not an issue, monitor if N_smear >> 100

11.4 Systematic Uncertainties
------------------------------

SOURCE 1: Section assignment ambiguity
    Events near section boundaries could be assigned differently
    Impact: Boundary regions have mixed parameters
    Mitigation: Use average position consistently

SOURCE 2: Background contamination in data
    Mass distribution may include non-π⁰ background
    Impact: Biases fit toward matching background shape
    Mitigation: Apply background subtraction before fitting

SOURCE 3: Simulation input kinematics
    If simulation kinematics don't match data, smearing can't fully compensate
    Impact: Residual discrepancies even after optimal smearing
    Mitigation: Validate simulation generator against data

SOURCE 4: Detector conditions during data-taking
    Gain drifts, temperature effects, rate-dependent effects
    Impact: Time-dependent calibration not captured
    Mitigation: Run smearing analysis separately for different run periods

APPENDIX A: MATHEMATICAL DERIVATIONS
================================================================================

A.1 Invariant Mass Formula Derivation
--------------------------------------
For two particles with 4-momenta (E₁, p⃗₁) and (E₂, p⃗₂):

Invariant mass squared:
    M² = (P₁ + P₂)² = (E₁+E₂)² - (p⃗₁+p⃗₂)²

Expanding the momentum term:
    (p⃗₁+p⃗₂)² = |p⃗₁|² + |p⃗₂|² + 2p⃗₁·p⃗₂

For massless photons (|p⃗| = E):
    M² = (E₁+E₂)² - [E₁² + E₂² + 2E₁E₂cos(θ₁₂)]
    M² = 2E₁E₂[1 - cos(θ₁₂)]

Using 1 - cos(θ) = 2sin²(θ/2):
    M_γγ = 2√(E₁E₂) sin(θ₁₂/2)

This shows mass depends on BOTH energies AND opening angle.

A.2 Position Smearing Effect on Invariant Mass
-----------------------------------------------
Opening angle between photons:
    cos(θ₁₂) = (p⃗₁·p⃗₂)/(|p⃗₁||p⃗₂|)

For photons at positions (x₁,y₁,z) and (x₂,y₂,z):
    cos(θ₁₂) = (x₁x₂ + y₁y₂ + z²) / (r₁r₂)

where r₁ = √(x₁²+y₁²+z²), r₂ = √(x₂²+y₂²+z²)

Position smearing: (x,y) → (x+δx, y+δy)
    δx, δy ~ N(0, σ_pos)

This changes:
    r → r' = √((x+δx)²+(y+δy)²+z²) ≈ r + (xδx+yδy)/r + O(δ²)
    cos(θ₁₂) → cos(θ'₁₂) ≈ cos(θ₁₂) + Δcos

For small δx, δy:
    Δcos ≈ [δx₁x₂+δy₁y₂+x₁δx₂+y₁δy₂]/(r₁r₂) - [corrections]

Propagating to mass: δM/M ≈ -Δcos/[2sin²(θ₁₂/2)]

For typical NPS geometry (z ~ 400 cm, x,y ~ 20 cm):
    Opening angles θ₁₂ ~ 5-10°
    Position smearing σ_pos ~ 0.5 cm
    Induced mass uncertainty: δM ~ 2-5 MeV

This is comparable to energy resolution effects, justifying the inclusion 
of position smearing in our model!

A.3 Chi-Squared Statistical Properties
---------------------------------------
For N_bins bins with data counts n_i and expected (smeared sim) counts μ_i:

    χ² = Σᵢ (nᵢ - μᵢ)²/nᵢ

Expected value: E[χ²] = N_bins - N_params ≡ Ndof (degrees of freedom)
Variance: Var[χ²] = 2 × Ndof

For our case: N_bins = 100, N_params = 3, so Ndof = 97
    E[χ²] ≈ 97
    σ(χ²) ≈ √(2×97) ≈ 14

Therefore, χ² values between ~70-120 are statistically consistent with 
good fit.

Reduced chi-squared: χ²_red = χ²/Ndof
    Good fit: χ²_red ≈ 1.0 ± 0.15

A.4 Monte Carlo Uncertainty in Chi-Squared
-------------------------------------------
When μᵢ (smeared sim) involves N_smear MC repetitions, each bin has 
additional variance:

    Var(μᵢ) = μᵢ/N_smear

This propagates to chi-squared:
    Var(χ²) = Σᵢ [4μᵢ²/nᵢ² × Var(μᵢ)]
            = Σᵢ [4μᵢ²/nᵢ² × μᵢ/N_smear]
            = (4/N_smear) × Σᵢ μᵢ³/nᵢ²

For μᵢ ≈ nᵢ (good agreement):
    Var(χ²)_MC ≈ (4/N_smear) × Σᵢ nᵢ = (4/N_smear) × N_total

Relative uncertainty:
    σ(χ²)/χ² ≈ √[Var(χ²)_MC]/N_bins 
             ≈ 2/√(N_smear × N_bins)

For N_smear = 50, N_bins = 100:
    σ(χ²)/χ² ≈ 2/√5000 ≈ 0.028 ≈ 3%

This confirms our empirical observations!

B.1 Example: Energy Smearing Implementation
--------------------------------------------
// Apply energy smearing to measured energy
double apply_energy_smearing(double E_meas, double mu, double sigma, 
                              TRandom3& rng) {
    // Draw random scale factor from Gaussian
    double scale = rng.Gaus(mu, sigma);
    
    // Protect against non-physical values
    if (scale <= 0) scale = 0.001;  // small positive value
    
    // Apply smearing
    double E_smeared = E_meas * scale;
    
    return E_smeared;
}

B.2 Example: Position Smearing Implementation
----------------------------------------------
// Apply position smearing to cluster position
void apply_position_smearing(double& x, double& y, double sigma_pos, 
                              TRandom3& rng) {
    // Add Gaussian noise to x and y independently
    x += rng.Gaus(0.0, sigma_pos);
    y += rng.Gaus(0.0, sigma_pos);
}

B.3 Example: Direct Invariant Mass Calculation
-----------------------------------------------
// Calculate invariant mass from two photon energies and positions
double calculate_invariant_mass(double E1, double x1, double y1,
                                double E2, double x2, double y2,
                                double z_nps) {
    // Calculate distances from target
    double r1_sq = x1*x1 + y1*y1 + z_nps*z_nps;
    double r1_inv = 1.0 / sqrt(r1_sq);
    double r2_sq = x2*x2 + y2*y2 + z_nps*z_nps;
    double r2_inv = 1.0 / sqrt(r2_sq);
    
    // Calculate momentum components
    double px1 = E1 * x1 * r1_inv;
    double py1 = E1 * y1 * r1_inv;
    double pz1 = E1 * z_nps * r1_inv;
    
    double px2 = E2 * x2 * r2_inv;
    double py2 = E2 * y2 * r2_inv;
    double pz2 = E2 * z_nps * r2_inv;
    
    // Calculate invariant mass
    double E_tot = E1 + E2;
    double px_tot = px1 + px2;
    double py_tot = py1 + py2;
    double pz_tot = pz1 + pz2;
    
    double m_sq = E_tot*E_tot - px_tot*px_tot - py_tot*py_tot - pz_tot*pz_tot;
    
    return (m_sq > 0) ? sqrt(m_sq) : 0.0;
}
