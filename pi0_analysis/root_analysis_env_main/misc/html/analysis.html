Data reconstruction and π⁰ selection

The per-run macro converts replay trees into a compact physics tree while retaining the cuts, backgrounds, fit diagnostics and event weights needed downstream.

On this pageInputsElectron selectionPhoton clustersPair physicsBackgroundsExclusivityOutputs

1. Inputs and run dispatch

The primary driver is src/analysis/run_parallel_nps_analysis_main.sh; each worker invokes nps_analysis_main.C. The driver selects rows from config/nps_dvcs_all_kins_main.csv by kinematic label, run, target/type and quality settings, then resolves either waveform or HCANA replay files.

Waveform source

Default production location: /lustre24/expphy/volatile/hallc/nps/hhuang/farmFile/Production/DVCS. Timing defaults are selected for waveform-calibrated branches.

HCANA source

Default replay location: /lustre24/expphy/cache/hallc/c-nps/analysis/pass2/replays/updated. The unified macro detects and binds the applicable branch schema.

Configuration is physics input. A matching Kin_old section in acceptance_cuts.conf is mandatory. Inheritance is explicit; missing sections fail rather than silently using unrelated cuts.

2. Establish the scattered-electron sample

The default data selection requires an event outside the EDTM pulser, a valid HMS track in acceptance, and electron PID:

From beam and scattered-electron four-vectors the analysis calculates (ν=E−E′), (Q²), (W), (x_B), and the virtual-photon direction. The precise implementation lives in nps_physics_var.h and the unified macro.

3. Turn NPS showers into photon candidates

Input multiplicity can reach the full 1080-block detector, while at most 20 clusters are processed by the analysis. Each candidate is filtered by:

  • cluster energy threshold (normally 1.5 GeV; 1.6 GeV for KinC_x36_5 and KinC_x36_5_407),
  • fiducial x/y limits,
  • mode-dependent timing window and inter-cluster timing, and
  • run-dependent dead columns, rows and individual blocks from dead_block_per_runs.csv.
Why the mask comes before pairing. A dead-region cluster must not influence which γγ pair is chosen. The selected pair therefore reflects the detector state for that run, not only a post-selection flag.

4. Reconstruct the two-photon system

Accepted clusters are paired and converted into photon four-vectors using their energies and directions from the nominal target origin. The pair defines the π⁰ candidate and the hadronic observables carried to extraction.

mγγ = √[2E₁E₂(1−cosθ₁₂)]
pπ⁰ = pγ1 + pγ2
t = (q−pπ⁰)²,   t′ = t−tmin

The tree stores (Q²,W,t,t_{min},p_T,θ,φ,s,x_B,z), both cluster positions and energies, HMS focal/target-plane variables, helicity and event identity.

5. Estimate accidentals and combinatorial background

Timing sidebands estimate accidental γγ coincidences. The active combinatorial model is the PEPSI-motivated positive Fermi-background implementation in nps_comb_bg_pepsi.h; the older polynomial model remains commented at the include point.

The producer constructs a mass-dependent signal estimate from accidental-subtracted and combinatorial-subtracted (m_{γγ}) spectra. The event branch pi0_weight is a signal estimate as a function of invariant mass—not a truth label and not automatically a differential background subtraction in (Q²,x_B,t′,φ).

Known inference limit. A marginal (m_{γγ}) purity weight does not guarantee unbiased signal yields in every physics bin if signal and background have different conditional kinematics. This must be tested in the final slices.

6. Define reconstructed exclusivity

The main weighted flag requires corrected missing mass in the configured window 0.8–1.1 GeV. Diagnostic alternatives include a de-correlation boundary, a classical ellipse and a robust MCD ellipse in the ((m_{γγ},M_X)) plane. Combined-level ellipse/MCD flags can be retrained after runs are merged.

Mass plane

The 2D view makes the π⁰ mass and proton missing-mass correlations visible. It is useful for acceptance and tail diagnostics.

Do not conflate labels

In data, exclusivity is a reconstructed cut. In simulation, is_exclusive has historically represented the generated channel. Equivalent reconstructed cuts must be verified explicitly.

7. Per-run output contract

output/<kin>/ ├── root/diagnostics_run<run>.root # physics tree + histograms ├── plots/run_<run>/... # cut/background diagnostics ├── summary/summary_run<run>.txt # readable run summary ├── summary/summary_all_runs.csv # rebuilt successful-run table └── logs/analysis_main_run<run>.log # full worker log

The wrapper reconstructs the per-kin summary using the macro’s [CSV_WRITTEN] marker. That marker and all output names are part of the pipeline contract.
