Stages 2–3 · exposure and combination

Efficiencies, livetime and run normalization

This stage answers how much luminosity and detector opportunity each run represents before events from different runs are combined.

On this pageGood intervalsMetricsLivetimeRun scaleCombinationUncertainty

1. One accepted-range definition feeds every metric

compute_efficiencies_stuff.cxx first identifies stable beam periods from HEL scalers. Defaults use quartet helicity, a 2.5 μA junk floor, 2.75 μA minimum mean current, a ±15% peak-current window, 30-point stability window and maximum 8% charge-fraction spread.

Selected physics events require event type 1 and g.evnum inside the accepted ranges. Scaler and event calculations then reuse those ranges, protecting against comparing efficiencies and charge from different time intervals.

Binomial errors are written for efficiency ratios. Runs with zero denominators are warned and cannot silently become valid corrections.

3. NewGen EDTM livetime

The current-window EDTM TDC peak is found by histogram-mode binning (width 10). Cached EDTM values in the peak window form the numerator; scaler intervals supply the production denominator. The prescale factor is applied explicitly:

LEDTM = (NEDTM,event peak / NEDTM,scaler) · PS

Additional accepted-event and accepted-evcount quantities are retained as diagnostics. Beam time, charge before/after good-event cuts, source file choice and segment coverage are also recorded.

4. Convert a run into corrected yield per charge

The combination code uses the product of tracking and hodoscope efficiency for its active detector correction:

εdet = εtracking εhodo
scalerun = PS / [(Qrun/1000) · LEDTM · εdet]

The charge division by 1000 converts μC to mC according to the combination code’s input convention. Relative livetime and efficiency errors are propagated to scale_err.

Event use downstream. A typical corrected data contribution is scale × pi0_weight. Where combined samples are compared per 1 mC, code may also apply the run’s fraction of total unique-run charge; the exact extractor/plotter contract should be checked before adding any extra charge factor.

5. Merge only runs with valid metadata

combine_analysis_branches.py loads each per-run physics tree and the matching efficiency row. Missing, nonfinite or nonpositive charge/efficiency/livetime values cause the run to be skipped. The merged tree gains run number, scale, charge, prescale, livetime, efficiency and their errors.

The combiner may also build combined-sample 2D exclusivity diagnostics and flags. The canonical product is:

output/<kin>/root/combined_branches_LH2.root

6. What the scale error does not cover

Included locally

  • Efficiency counting errors
  • NewGen EDTM propagated error
  • Run-by-run charge/prescale/livetime metadata

Separate or later

  • Target-density/contamination correlated normalization
  • Background-model uncertainty in pi0_weight
  • Acceptance, radiative and model-shape uncertainty
  • Residual detector-response systematics
Current project rule: efficiency computation is frozen for this phase. Treat changes as controlled physics changes requiring representative reruns and value comparisons.
